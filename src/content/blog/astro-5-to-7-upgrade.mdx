This site used Astro 5. It uses Astro 7 now. This post shows what I changed. It also shows the problems that I found.

I wrote this post in Simplified Technical English (ASD-STE100). This is a controlled language for technical documents. It uses a small set of approved words and short sentences.

<Callout type="info" title="Summary">
I moved this site through two major versions in one step. The largest changes were the content collections API, Tailwind CSS 4, and a new Markdown processor. The site has one less dependency than before.
</Callout>

## Why I did this work

Astro 5 came out in 2024. Two major versions came after it. Each major version has changes that break the code.

If you wait, you get more work to do at one time. Two small upgrades are easier than one large upgrade.

## Before you start

Do these steps first:

1. Read the release notes for each major version. Do not read only the last one.
2. Look at each integration. Find out if it works with the new version.
3. Make sure that your tests run correctly.

<Callout type="warning" title="An integration can stop an upgrade">
The `@astrojs/tailwind` integration does not work with Astro 6 or a later version. I had to install Tailwind CSS in a different way. Look for problems like this before you start.
</Callout>

## Node.js

Astro 7 needs Node.js 22.12 or a later version. This site used Node.js 18.

Change the version in all of these locations:

- `.nvmrc`
- `netlify.toml`
- the `engines` field in `package.json`

If you forget the deploy configuration, the build works on your computer. But it fails on the server.

## The content collections API

Astro 6 removed the old content collections API. This was the largest change to the code.

Do these steps:

1. Move `src/content/config.ts` to `src/content.config.ts`.
2. Add a loader to each collection.
3. Change `entry.slug` to `entry.id`.
4. Change `entry.render()` to `render(entry)`.

Astro does not find your files without a loader. You must tell it where the files are.

<CodeComparison title="The collection configuration" beforeLabel="Astro 5" afterLabel="Astro 7">

<div slot="before">
```ts
// src/content/config.ts
import { defineCollection, z } from 'astro:content';

const blog = defineCollection({
  type: 'content',
  schema: z.object({
    title: z.string(),
  }),
});
```
</div>

<div slot="after">
```ts
// src/content.config.ts
import { defineCollection } from 'astro:content';
import { glob } from 'astro/loaders';
import { z } from 'astro/zod';

const blog = defineCollection({
  loader: glob({
    pattern: '**/*.{md,mdx}',
    base: './src/content/blog',
  }),
  schema: z.object({
    title: z.string(),
  }),
});
```
</div>

</CodeComparison>

The `body` property can be empty now. Give it a default value before you use it. My code counts the words in each post. Without this test, it stopped at the first post.

Also import `z` from `astro/zod`. The `astro:content` module still gives you `z`, but Astro shows a warning.

## Tailwind CSS 4

Tailwind CSS 4 keeps its configuration in the CSS file. I removed `tailwind.config.mjs`.

Two lines replace the old configuration:

```css
@import 'tailwindcss';
@custom-variant dark (&:where(.dark, .dark *));
```

The first line replaces the three `@tailwind` lines. The second line keeps the dark mode that uses a class. Without the second line, all the `dark:` classes stop.

## The new Markdown processor

Astro 7 has a new Markdown processor. Its name is Sätteri. It replaces remark and rehype.

I was not sure about Expressive Code, because it uses a rehype plugin. But it works correctly. Astro connects it to the new processor.

## The new compiler

The old Astro compiler used the Go language. The new compiler uses the Rust language.

The new compiler finds more errors than the old compiler. If an HTML tag has no end tag, the build stops.

## Code blocks

I added Expressive Code. It controls all the code blocks now.

It gives these functions:

- A button that copies the code
- Marks for the lines that you add or remove
- Frames that look like an editor or a terminal
- Sections that open and close

The cost is small. Expressive Code adds 18.6 kB of CSS and 2.5 kB of JavaScript.

<Callout type="danger" title="Two CSS rules can have the same specificity">
My CSS set a background color for each `pre` element. Expressive Code sets its own background color. The two rules had the same specificity. Thus the sequence of the CSS decided the result. I made my rule more narrow with `:not()`.
</Callout>

## Icons

The site used emoji for its icons. Emoji do not look the same on all systems. Thus I changed them to SVG icons.

I did not add a library. Astro reads an SVG file as a component:

```astro
---
import Info from '../icons/info.svg';
---

<Info class="w-5 h-5" aria-hidden="true" />
```

I put ten Lucide icons in `src/icons`. Their total size is 4 kB.

I looked at two other methods first:

- `astro-icon` works correctly. But no new version came after December 2024. It also adds a `symbol` element and a `use` element to each icon.
- `lucide-static` installs 61 MB. Most of this is fonts and bundles. It gives you the same 4 kB of icons.

Ten icons do not need a dependency.

## Accessibility

Each emoji had the `aria-hidden="true"` attribute. Thus a screen reader did not read it.

Only the color and the emoji showed the type of each callout. A person who uses a screen reader got no information about the type. There was no difference between a warning and a tip.

I added a hidden label to each callout. The label says `Warning:`, `Tip:`, or `Danger:`. A screen reader reads the label. A person who looks at the screen does not see it.

<Callout type="tip" title="When to hide an icon">
Hide an icon from a screen reader only if the text near it gives the same information. If the icon gives the information alone, add a text label.
</Callout>

## What I learned

- Read the release notes for each major version. Do not read only the last one.
- Look at the integrations before you start. An integration can stop the work.
- Look at the HTML that the build makes. A build with no errors is not enough.
- Open the site in a browser. Some problems appear only there.
- Count your dependencies. A framework can do the work of a library.
